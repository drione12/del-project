# Memory Master

Windows 전용 파일 검색 + 강제 삭제/정리 도구. 이 저장소의 `src/`(Everything 클론,
C++/Win32)와는 별도의 Python/PyQt5 앱으로, 대부분의 기능은 코드를 공유하지 않고 빌드/CI도
따로 돕니다 — 다만 파일 검색 페이지만은 예외로, 관리자 권한으로 실행 중이면 `src/`의 검색
엔진을 `EverythingCore.dll`(`core_api.h`가 감싼 raw NTFS MFT 인덱스 + USN 저널 실시간
감시)로 이 프로세스 안에 `ctypes`로 직접 불러와 씁니다 (아래 "파일 검색" 항목 참고) — 별도
`EverythingClone.exe` 프로세스를 띄우고 그 창을 심는 방식이 아니라, 이 앱 자체의 검색
기능이 됩니다.

## 왜 별도 앱인가

목업 디자인(둥근 카드, 그라디언트, 커스텀 타이틀 바)을 제대로 구현하려면 커스텀 그리기가
많이 필요한데, Qt(QPainter + QSS)가 raw Win32 GDI보다 훨씬 적합하고 검증된 방법입니다.

## 기능 (사이드바 4개 아이콘)

원래는 RAM 게이지/CPU·Swap 추이/메모리 할당/상위 프로세스를 보여주는 **대시보드** 페이지가
맨 위에 하나 더 있었지만, 사용자 요청으로 페이지와 그 전용 코드(`core/metrics.py`,
`core/optimizer.py`, `core/memory_allocation.py`, 게이지/차트 위젯 등)를 전부 제거했습니다.
강제 삭제 파이프라인이 쓰는 `core/critical_processes.py`·`core/processes.py`와 시작 프로그램
페이지가 쓰는 `core/system_health.py`·`widgets/status_pill.py`는 계속 씁니다.

- **정리** — 중복 파일 찾기(MD5), 중복/유사 이미지 찾기(퍼셉추얼 해시 + OpenCV ORB로
  잘린/부분 일치까지 탐지, 폴더 여러 개 지정 가능), 검토 다이얼로그(미리보기 확대/축소,
  우선 유지 폴더 자동 선택), 파일/폴더를 끌어다 놓으면 강제 삭제 파이프라인으로 바로
  연결되는 드롭 영역. 파일/이미지 검색과 강제 삭제 실행 중에는 중지 버튼으로 취소할 수
  있습니다.
- **파일 검색** — 관리자 권한으로 실행 중이면 `src/`의 검색 엔진을
  `EverythingCore.dll`(`core/fast_search.py`가 `ctypes`로 불러 씀)로 이 프로세스 안에서
  직접 돌립니다(raw NTFS MFT 인덱스 + USN 저널 실시간 감시라 진짜로 즉시 검색됨) — 화면은
  아래 설명하는 이 페이지 자체의 테이블/미리보기/컨텍스트 메뉴를 그대로 씁니다. 예전에는
  별도 `EverythingClone.exe`를 띄워 그 창을 이 페이지 안에 자식 창으로 심는 방식이었는데,
  그러면 프로세스가 둘로 나뉘고(EverythingClone은 항상 관리자 권한 필요, 이 앱은 아닐 수도
  있음) Windows가 서로 다른 권한 수준 사이의 창 부모-자식 연결을 막거나 제한하는 문제
  (UIPI)가 있었습니다 — 지금은 애초에 별도 프로세스도 별도 창도 없어서 그 문제 자체가
  존재하지 않습니다. 관리자 권한이 없으면(또는 `EverythingCore.dll`을 찾지 못하면) 대신
  이 앱 자체의 Python/os.walk 기반 폴백 검색을 보여주고, 상단 배너의 "관리자 권한으로
  다시 시작" 버튼으로 앱을 관리자 권한으로 재시작하면(재시작 후 자동으로 파일 검색
  페이지로 돌아옵니다) 그 즉시 빠른 검색 쪽으로 전환됩니다. 폴백 검색은 폴더를 고를 필요
  없이 페이지를 처음 열면 연결된 모든 고정 드라이브를 자동으로 인덱싱하고("다시 인덱싱"
  버튼으로 새로고침 가능), 검색어 입력 즉시 결과가 표시됩니다. 결과 테이블은
  이름(아이콘 포함)/경로/크기/수정한 날짜/생성한 날짜/액세스한 날짜/확장자/속성 8개
  컬럼으로, `src/`의 EverythingClone이 자기 네이티브 창에서 보여주는 컬럼과 이름·순서·
  형식(날짜는 24시간제 "YYYY-MM-DD HH:MM", 속성은 R/H/S/D/A/C/E/T/O/L 글자 조합)까지
  전부 동일합니다 - 어느 백엔드로 찾았든 화면에서는 구분이 안 갑니다. 검색창 오른쪽의
  "카테고리:" 드롭다운(전체/음악/압축파일/문서/
  실행파일/폴더/이미지/비디오)으로 결과를 종류별로 좁힐 수 있고(확장자 기준, 검색어와
  함께 쓸 수 있음), 이 분류는 `src/`의 EverythingClone과 동일한 기준을 씁니다 - 이
  페이지는 EverythingClone 쪽에 새 기능/UI가 생길 때마다 계속 맞춰서 따라가는 것을
  원칙으로 합니다(엔진을 직접 불러 쓰는 지금은 특히 더 그렇습니다 - 빠른 검색 쪽은
  말 그대로 같은 엔진이니까요). 결과 테이블과 미리보기 패널은 스플리터로 나뉘어 있어
  가운데 경계선을 마우스로 드래그해 비율을 자유롭게 조절할 수 있고, 이름 컬럼을 포함해
  모든 컬럼 경계도 직접 늘릴 수 있습니다(이름 컬럼은 기본 너비도 여유 있게 잡아 파일명이
  잘 안 잘리게 해뒀습니다). 이미지 파일을 선택하면 옆에 미리보기가 자동으로 크기를
  맞춰 표시되고, 스플리터로 미리보기 패널 크기를 바꾸면 그 즉시 원본 비율을 유지한 채
  다시 맞춰집니다. 동영상 파일(mp4/mkv/avi/mov/wmv 등)을 선택하면 첫 프레임을
  추출해 같은 방식으로 썸네일로 보여줍니다(백그라운드 스레드에서 추출하므로 큰
  파일이어도 화면이 멈추지 않습니다). Shift/Ctrl로 여러 항목 다중 선택, Del 키로 휴지통 이동, 우클릭 메뉴로
  열기/폴더 열기/삭제/강제 삭제(단일 선택은 프로세스 종료 목록 확인 포함, 다중 선택은
  일괄 처리)를 지원합니다 - 빠른 검색/폴백 검색 두 백엔드 모두 이 삭제 파이프라인은
  완전히 동일합니다(`core/force_delete.py`, 항목의 경로만 있으면 되므로 어느 백엔드가
  찾았는지는 상관없음). 긴 경로/삭제 안정성 개선(장문 경로 지원, `pywin32` 기반 휴지통
  백엔드)이 포함되어 있으나 실제 Windows 환경에서 재확인이 필요합니다. (두 백엔드 모두
  실제 Windows 환경에서 재확인이 필요 — 특히 `EverythingCore.dll` 쪽은 이 세션에서 완전히
  새로 만든 기능입니다.)
- **설정** — 다크/라이트 테마, 항상 위에 표시, 창 투명도, 격리 폴더 위치.
- **시작 프로그램** — 레지스트리 Run 키 + 작업 스케줄러 항목(아이콘 표시), 부팅
  영향도(낮음/보통/높음, 색으로 구분) 추정, 레지스트리 항목 추가/제거.

모든 강제 삭제는 하나의 공통 파이프라인(`core/force_delete.py`)을 거칩니다: 보호 경로
차단(`core/path_guard.py`) → 사용 중인 프로세스 확인(관리자 권한 없이는 소유권 변경 시도 안 함) →
확인 다이얼로그로 종료될 프로세스 목록 표시 → 실행(진행률/취소 가능, 필요 시 재부팅 후 삭제
예약, 선택적 3-패스 보안 삭제). 보호 경로는 두 등급입니다 - `System32`/`Program Files`/
`Program Files (x86)`/pagefile.sys/bootmgr 등은 예외 없이 완전히 보호되고, `C:\ProgramData`와
`C:\Windows\Installer`는 폴더 자체는 삭제할 수 없지만 그 안의 개별 파일/폴더(설치 프로그램이
남긴 잔여 파일 등)는 강제 삭제를 시도할 수 있습니다 - 이때 기존 읽기 전용 해제/소유권 획득
재시도 로직이 실제로 동작하게 됩니다. 휴지통으로 이동(Del 키/"삭제")도 동일한 보호 경로
차단을 거치고, 첫 시도가 권한 문제로 실패하면 읽기 전용 속성만 가볍게 해제하고 한 번 더
시도합니다(전체 소유권 획득까지는 하지 않음 - 그래도 안 되면 "강제 삭제"가 다음 단계).

## 개발

```powershell
pip install -r requirements.txt
pytest tests -v
```

`tests/`는 순수 로직 + 실제 파일시스템 I/O(임시 파일 기준)를 테스트합니다 — 실제 Windows
API(`ctypes.windll`, `winreg`)를 쓰는 코드는 이 코드가 실행되는 개발 환경(Linux)에서는
GitHub Actions(windows-latest)로만 검증됩니다. PyQt5 위젯은 `QT_QPA_PLATFORM=offscreen`
로 헤드리스 환경에서도 직접 구성/렌더링해 검증합니다 (`scripts/smoke_check.py`).

## 빌드

GitHub Actions에서 워크플로를 수동 실행(`workflow_dispatch`)하면 PyInstaller로
단일 실행 파일을 패키징해 아티팩트로 올립니다 (`.github/workflows/build-memory-master.yml`
의 `package` 잡). 로컬에서 직접 만들려면:

```powershell
pip install pyinstaller
pyinstaller --noconfirm --onefile --windowed --name MemoryMaster --add-data "resources;resources" main.py
```
